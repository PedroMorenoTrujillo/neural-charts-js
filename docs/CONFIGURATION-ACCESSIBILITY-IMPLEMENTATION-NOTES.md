# Next implementation details — configuration/accessibility

Current status: the implementation and measured gates are recorded in [Five-point closure](FIVE-POINT-CLOSURE-2026-11-04.md). The initial plan/design below is retained as history; its ACTIVE/PENDING implementation labels are superseded by that report. Human reviews and unapproved bundle budgets remain pending.


This is a private working design for the already-authorized next checkpoint, not documentation of APIs that already exist. Finish measured performance/bundle corrections first; continue implementing without another prompt. No public frozen Core semantics or NC-01A changes.

- Keep numeric/date formatting declarative and serializable, with cached Intl instances rather than one formatter per point. Support precise locale/currency/fraction/notation/timezone configuration, consistent labels/tooltip/accessibility. Raw CSV and original-value table remain exact. Numeric/time ticks need raw tick values in the public frame where formatting strings alone lose information; extend optional metadata through Core rather than reverse-parsing localized dates.
- Add presentation by stable series ID (color, dash, marker shape/radius, opacity/fill/pattern where meaningful). Keep data readonly and free of styles. Render real shapes/patterns, legend swatches and focus with shared resolved styles; no empty configuration fields. Safe internal SVG IDs and no external resources.
- Responsive policy: bounded ordered minWidth/maxWidth rules with nested overrides for legend/appearance/axes/tooltip/height. Conditions use the owning container, never the chart's overridden width. Preserve the original base options separately from resolved options so widening restores the base. Forbid recursive rules/data/state overrides; one existing observer and no feedback loops. Pure SSR resolution uses known configured size.
- Accessibility: configurable chart/series/point descriptions and keyboard policy; indexed navigation stays fast. Use showDetail's existing announce argument so pointer hover does not flood the live region by default. Announce keyboard and optional real data updates through a deduplicated, bounded policy with one owned cancellable timer if coalescing is needed. Keep truthful labels/values, full table access, forced-colors/patterns and human screen-reader review pending.
- Verify 320/375/430/768/narrow desktop, resize out/back, mobile first/last active datum, RTL, dark/high contrast and zoom 200/400%. Extend real showcase controls, executable examples, English/Spanish guides and public API reference. Every option must affect actual output and have meaningful invalid/edge cases.
- Missing variants: extend Core's shared area/stacking path to stacked areaspline and mixed stacking without editing frozen math. Preserve sign-separated totals, null semantics, original values, IDs and shared normalization. Add real variants to authoritative recipe generation; do not add new family aliases. Export composition must include visible title/legend in SVG/PNG without a second chart renderer.
- Remaining report capabilities (financial navigator/grouping, drilldown/selection interactions, annotations, motion/export/audio extras) remain in the authorized backlog. Do not mistake the first performance milestone for completion of the user's whole request. Preserve no-push/no-publish/local-only restrictions.
