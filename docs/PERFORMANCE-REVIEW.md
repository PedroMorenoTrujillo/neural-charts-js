# Performance investigation — 2026-11-03

The historical sine-wave scenarios and their original `artifacts/performance.json` are preserved. `node tooling/compare-performance.mjs` runs three sequential repetitions of the same script, changing only its output filename. All repetitions, their environment, script/baseline hashes and candidate receipt are retained. Run this with browser/build campaigns idle.

The first comparison found a reproducible planning regression above20% at10,000 Line points. The root Core dispatcher owned the input and then called the new public Cartesian boundary, which owned it again. The fix belongs to the shared Core worktree: its private owned-input boundary reuses the sanitized value; the public entry still performs all ownership and validation. Mutation/accessor isolation and public/root frame parity are tested. No frozen foundation file or public API changed.

After the correction,10,000-point planning p95 was56.316/55.050/58.223ms across the three repetitions, versus54.284ms in the historical baseline. Serialization was16.946/16.341/16.558ms versus17.051ms. No large-data planning regression over20% reproduced in all three repetitions. The prior candidate measurements remain under `artifacts/performance-checkpoints/`.

The remaining reproducible relative increase is30-point Column serialization:0.138/0.168/0.159ms versus0.113ms. The serialized output has87 SVG nodes versus76 because the corrected axis labels now use independently positioned text runs and accessible full-text groups. This is a measured absolute increase of0.025–0.055ms, not an unexplained scaling failure. The change fixes demonstrated mobile clipping and Firefox RTL bounds and is retained. It does not change the benchmark dataset or its acceptance thresholds.

`node tooling/benchmark-v1.mjs` separately records118 basic families and six capacity scenarios in Chromium,Firefox and WebKit:372 scenario rows,10 measured samples plus two warmups per row. Phases include initial owner/layout, immutable replacement, resize, selection, available zoom/pan and real SVG/CSV serialization. Line50,000, Scatter10,000 and Column3,000/5,000 logical observations retain their original data. Per-row SVG node counts, browser versions, Node/OS/CPU, bundle hash and Core receipt are recorded.

These are synchronous API plus forced-layout measurements. They do not establish sustained FPS, physical-device latency or a retained-heap byte budget.
